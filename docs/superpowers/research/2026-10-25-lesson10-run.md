# Lesson 10's run: two attempts, one censored session, no arm

Date: 2026-10-25 (session stamps are 2026-10-26). LC.19, lesson 10, "One spec
file per phase". Preregistration:
[2026-10-25-lesson10-preregistration.md](2026-10-25-lesson10-preregistration.md).

**What is measured.** That the preregistered arm could not run: in two
attempts the `joined` arm hung on a foreground server before finishing phase 1,
and one session was censored at its deadline with all 18 expected checks
missing. No session completed, so the spec-layout question has no reading, and
under the preregistration's own rule the arm is **void**.

**What is conjecture.** That the thin briefs invite the hang; that a server
guard would stop it; that the two spec layouts would or would not separate. None
of those has an arm.

Two things in that table are instrument findings, not lesson findings:

- **`wall` is 448 s for a session the deadline ended at 2700 s.** The trace
  stopped at the hang, and `report()` derives wall from trace timestamps. This is
  the third instance of the `wall` backlog entry's defect, and its largest
  understatement so far (70 s and 180 s were the others).
- **`leaked` names a node process in `pi`'s group and not the server.** The
  uvicorn processes ran in their own process group — `pi`'s bash tool puts each
  command in a new session — so neither the kill nor the sweep reaches them. The
  consequence was already on disk: a `uv run uvicorn app:app --port 9000` from
  run `20261025T112212Z-medium-31816b` was still alive 1 day 7 h after its run,
  holding its port. Both are now backlog entries.

## The rule, applied

The preregistration fixed: a censored session is censored, never a failure;
fewer than two uncensored sessions in an arm makes that arm **void**; only then
compare phase-4 missing counts.

- The `joined` arm produced **zero uncensored sessions**: one censored, one
  orphaned before it could be scored, one never started.
- Therefore the arm is **void**, and with the `split` arm never run there is no
  comparison, no null, and no separation. A void arm is not a null: a null would
  say the layouts did not separate, which this run cannot say.

The preregistration's own risk clause — "all six hanging is ~4.5 h and two void
arms; the rule above already covers that outcome" — is what happened to the
first arm in under an hour.

## What this means for lesson 10

The lesson's page cannot rest on this run. Its subject is a layout habit, and
the instrument could not get a worker as far as phase 2, let alone phase 4, in
either attempt: the only scored session missed **every** check, phase 1
included. Writing the page now would either cite the retired ladder finding or
state a `conjecture` with no arm behind it.

LC.19 is therefore **blocked on the foreground-server pathology**, not on spec
layout. That question already has an owner and a dormant answer: the three-way
arm (facts bullet, dormant guard on `lc11b-server-guard` at `420ba1d`, both) in
the backlog's foreground-server entry, which needs LC.5 and runs as LC.7A. The
thin briefs and the per-module reading are built and can be reused unchanged
once a worker stops hanging.

## What would falsify this

- A session under the same briefs that **completes** would say the hang is not
  universal, and one more attempt would be worth its wall.
- A run with the server guard that completes while these briefs hang would put
  the cause on the worker rather than on the briefs, which is the reading LC.7A
  wants anyway.
- A run whose record shows `specs` differing from its arm, or a `joined`
  workspace without `specs/roadmap.md`, would make the scores unattributable.
  Neither fired: the one scored session carried `specs: joined` and the joined
  workspace.

## Risks

- **Reading a censor as a failure.** The censored session's 18/18 could be
  misquoted as "the joined layout failed every check". It did not fail them; it
  never reached them. Any table that quotes it owes the `deadline` marker beside
  it.
- **Counting the aborted attempts as runs.** Attempt 1 produced no record at
  all, and attempt 2 produced one censored session of a planned six. n = 1
  censored, not n = 3.
- **Repeating the cost.** Each hang costs a full deadline. Two attempts cost
  ~2 h; a third attempt before the worker or the briefs change would cost the
  same and expects to learn the same.

## Attempt 3 (2026-10-26): the hang is fixed, the scoring is not yet measuring

Three instrument changes, preregistered in amendment (2), then a rerun.
`joined` session 1: 20:43:27 – 20:57:27Z, **840 s, `agent_settled`, no
`deadline` marker**, 56 requests, 52 tool calls, 5 tool errors, 13,192 peak
context, 30,043 output tokens, 0 nudge fires, `out_of_layout: []`,
`leaked: []`. It reported all four phases implemented, each with "the test
command … exited with code 0". **No hang**, and no censor: on one session, the
instructional changes were enough.

It then scored `failed_checks: 18`, and that number is **not 18 failures**.
Re-running the grader on that session's own workspace:

- `ERROR grader_tests/test_phase2_board.py`, `ERROR
  grader_tests/test_phase4_resolve_reopen.py`: `ModuleNotFoundError: No module
  named 'models'`, which aborts collection — `Interrupted: 2 errors during
  collection`. pytest ran nothing, so every expected id was absent and counted
  as missing, phase 1's four included.
- Phase 1 alone: **3 of 4 PASSED**, one FAILED
  (`test_home_html_element_declares_english_language`).

The workspace has no `models.py`: the worker put `class Complaint` in `app.py`.
**Nothing in the spec asked for `models.py`** — `specs/roadmap.md` names only
`app.py`, and `specs/tech-stack.md` says "run via `app.py`". The detailed
prompts used to say "Add a stable `id: int` field to the `Complaint` dataclass
in `models.py`" and "`<html lang="en">`"; the thin briefs do not, because the
spec they point at does not.

Two findings:

1. **The hang was instructional.** The story's in-process check, the briefs'
   verification line and a seeded test were enough for one session to finish all
   four phases in 840 s. One session is not a rate, and the guard question stays
   open for arms that wander, but the instrument no longer hangs by default.
2. **The spec is not a requirements document, and the arm needs one.** A brief
   that points at `specs/` can only ask for what `specs/` says; medium's roadmap
   is story-level while the grader enforces a file layout and markup that only
   the detailed prompts ever stated. Until the spec carries the criteria, the
   joined/split comparison measures how a model guesses, not how it finds a
   phase.

The run was stopped after session 1, with session 2 three minutes in, rather
than spending four more sessions on a reading that cannot separate the arms.

### The rule, applied

The preregistered rule compares the phase-4 `missing` count and fires only if
every uncensored session of one arm misses strictly fewer than every uncensored
session of the other. Excluding the two `checks_ran: false` sessions:

- `joined`: {5, **0**}
- `split`: {**0**, 3}

0 against 0 is a tie, so the arms do not separate: **a null on phase 4**, and the
same on total missing (`joined` {13, 1} against `split` {4, 10}). Passes are 0/3
for both arms, so the null holds on the pass reading too. Steps 3 and 5 of the
page stay `screen`; no `reference-run`.

### What the run does establish

1. **The acceptance criteria, not the layout, are what made the task reachable.**
   Before the spec carried them, no session got past import (18/18, `checks_ran:
   false`). With them: 13, **1**, 4 and 10 missing, and phase 4 clean twice — once
   in each arm. The instrument finally has headroom where it had none.
2. **`checks_ran` paid for itself on its first run, twice.** `joined` `6e7fdb`
   left `app.py` with `SyntaxError: unterminated triple-quoted string literal`;
   `split` `29dbd6` left a `Complaint.__init__() missing 1 required positional
   argument: 'timestamp'`, so `models.py` cannot seed itself. Both read as 18/18
   missing; both are workspaces that do not import. Neither is the spec layout.
3. **Cumulative checks catch layout regression.** `split` `995575` passed every
   phase-3 and phase-4 check while missing 3 of the 4 phase-1 checks: the later
   phases overwrote `templates/base.html`'s conventions — doctype, `lang="en"`,
   nav — instead of extending them. A working board on a page that no longer
   looks like the clinic.
4. **`joined` `5d07a2` wrote `pyproject.toml`, one path outside the layout.** The
   first out-of-layout write in any recorded arm; the check reported it, and the
   session still scored 13 missing.

### What it cannot say

- n = 3 per arm with 2 sessions per arm reaching phase 4 is too thin to separate
  anything, and the rule was written to say so rather than to look for a trend
  inside it.
- Medium still floors on passes (0/3 both arms), so the only reading with
  headroom is the per-module one; a pass-rate claim would need a task above the
  pass floor, which medium is not.
- Two of six sessions never ran their checks, so the effective n for the
  comparison is 2 per arm, not 3.
