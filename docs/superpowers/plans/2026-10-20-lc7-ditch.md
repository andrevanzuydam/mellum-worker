# LC.7 The ditch implementation plan

**Goal:** A bounded demonstration of base Pi failing an open-ended AgentClinic prompt session, the lesson that reads it, and the track renumbered.

**Design:** The harness gains `--deadline` (per session, default 600 s) before the demo: a session must be able to fail without taking the host down. The ditch is one session, one machine, n = 1, and says so. The unbounded first attempt (15 min, Node OOM) is named as the reason for the bound, not used as a rate.

- [ ] **Step 1:** `--deadline` in `run_task`, `run` and `suite`: kill the child on timeout, keep the run, mark `deadline`, and print it. Test with a sleeping fake.
- [ ] **Step 2:** Run the three-prompt AgentClinic session with `--deadline 120` against llama.cpp (approved).
- [ ] **Step 3:** Write `learn/getting-started/ditch.md`: the prompts, what the transcript shows, the pathologies, and the rule *evidence before a fix*. Renumber harness to lesson 3 and suite to lesson 4 (pages, index, nav, tests).
- [ ] **Step 4:** Changelog, roadmap Status, `## Result`, archive; `npm test`, caps, build; merge.

## Global Constraints

- No new run beyond the single bounded ditch; n = 1 and the page says it.
- The lesson shows observed behaviour, not a scripted list; the Pathologies page is the catalogue.
- `~/.pi` stays untouched; the session dir is inside the run.
